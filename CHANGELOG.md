# Changelog

## 2026-11-27

- `ColorRelief`, `gdaldem color-relief -alpha` as a transform: one band in, four u8 bands out, red, green, blue and alpha, continuous and with no nodata. It takes a jung-core `ColorFile`, a `ColorSelection` (interpolate, exact or nearest) and an optional `ValueRange` that percent stops resolve against and that `ColorRelief::new` requires when the file has one. Nodata cells take the `nv` colour, or transparent without one. Layer files take `kind = "color_relief"` with `color_file`, `selection` and `range` as the layer's last op, and its tiles serve as RGBA PNG through the new `encode::png_rgba`. A raster layer takes `ramp = "<gdaldem colour file>"` in place of `gray`, its PNG coloured through `encode::png_color_relief`, which runs the same `ColorRelief::rgba` the element does. `GrayConfig` is `RangeConfig`, and the server's PNG encoding comes from `LayerConfig::png_encoding`
- jung locked to cb34b91 for jung-core, which brings jung-mvt's rounding of tile coordinates to the nearest unit to `.mvt` tiles
- terrano-core locked to 4e25733 with its `turbojpeg` feature: `cog` layer sources, `geoplumb info` and `geoplumb run` read JPEG tiles and strips through libjpeg-turbo, equal to GDAL's read, and lossless and lossy WebP. `geoplumb info` names them `jpeg` and `webp`. Building geoplumb now needs cmake and a C compiler, and nasm for libjpeg-turbo's SIMD code
- `ClipRaster`, a fan-in of a raster and a polygon input, is `gdalwarp -cutline` without `-crop_to_cutline`: the raster's grid, bands, dtype and value kind stay, and every pixel whose centre lies outside the polygons, holes included, becomes nodata in every band. Each chunk pulls only the polygons reaching it and burns them by `rasterize`'s pixel centre rule, so chunks agree at seams, and a polygon input in another crs gets a reproject spliced. `ClipRaster::new` takes a nodata value for integer bands without a sentinel, which becomes the sentinel. The layer file op is `clip_raster` with `cutline`, the name of another layer of the file, and an optional `nodata`. A cutline layer missing from the file or with a `clip_raster` of its own fails at parse. `build_layer_graph` takes the file's layers beside the one it builds
- terrano-core locked to 30e5ff4: `cog` layer sources, `geoplumb info` and `geoplumb run` open BigTIFF, which GDAL writes past 4 GB or with `BIGTIFF=YES`
- terrano-core locked to 4af0228: `cog` layer sources, `geoplumb info` and `geoplumb run` read ZSTD tiles and strips, GDAL's `COMPRESS=ZSTD`, and `geoplumb info` names that compression `zstd`
- terrano-core locked to 5a2275b: `cog` layer sources, `geoplumb info` and `geoplumb run` open striped and band-interleaved GeoTIFFs, the layouts `gdal_translate` writes without `-of COG`, and pixel-interleaved multi-band files with the floating-point predictor read right, where every pixel used to read wrong
- `geoplumb pyramid <layers.toml> <layer> --bbox west,south,east,north [--min-zoom] --max-zoom [--t] -o <dir>` writes every xyz tile covering the bbox as `<dir>/z/x/y.png`, or `.mvt` for a vector layer, each the bytes `/tiles` serves for it. `XyzTile::covering` gives the tiles covering a lon/lat bbox at one zoom, and the `pyramid` example uses it
- a `stac` asset at the source's pixel size whose grid is off the window's, an item tiled on another origin say, is read on its own grid and resampled onto the window by value kind, as coarser assets are, instead of rounded onto the window's grid, which read continuous values up to half a pixel off. Assets on the grid read as before
- topoi-core locked to 2654af7, on i_overlay 9.2.1, which binds each dissolved hole to its own shell itself. `polygonize` output is unchanged: the 1024 px WorldCover window still matches GDAL in polygon count, hole count and area for every class
- a spill file write that finishes after its chunk was invalidated no longer replaces or deletes the file of the chunk recomputed after it. The rename into place runs under the cache lock and only while the entry still holds the chunk written, so an evicted and reloaded entry never reads the older chunk and never loses its file to the older write
- the unary `MapAlgebra` ops `add`, `sqrt`, `log` and `multiply` by a positive factor keep `Peak` over a peak input, so `log` of a flow accumulation keeps its one-cell channels through reprojection, tiles and export overviews. `abs`, `multiply` by zero or less, and every unary op over a continuous or categorical input still output `Continuous`

## 2026-11-26

- sources serve their native sample format. `CogSrc` serves the file's format and nodata through terrano's `read_window_typed`, refuses a file whose levels differ in either, and refuses an integer file with a transparency mask and no nodata at open. `CogSrc::open` takes a nodata value, the `cog` layer source's new `nodata` key, which marks cells equal to it and masked cells absent and is the integer sentinel. `StacSrc` serves each asset's dtype under `latest`, `min` and `max` and f64 under the other composites, refuses at open an integer asset with no nodata, and fails a pull on an item whose asset dtype differs from the anchor's. `GdalSrc` reads UInt8, UInt16, Int16, UInt32, Int32 and Float32 bands in their own type and every other type as f64. `Viewshed` outputs u8 with nodata 255, reclassify the smallest integer dtype holding every class value with its top value as nodata, or f64 for a fractional class, and `ToRaster` f32. `GET /export/{layer}`, `geoplumb run` and `.tif` tiles of such layers are written in that format. `.tif` tiles are now one uncompressed tile written by terrano's `write_cog_tiles`, with the integer nodata as GDAL_NODATA, in place of a striped f64 GeoTIFF, and `encode::geotiff` takes a palette. A one-band layer whose samples come unchanged from a `cog` with a colour table carries it into the export and the `.tif` tile through the new `Source::palette` and `Engine::palette`, and a layer with a computing element carries none. A `cast` layer op, `kind = "cast"`, `dtype = "u8"` and an optional integer `nodata`, builds `Cast::new`, which narrows by the same rounding, saturation and sentinel step as resampling, and every `Cast` refuses to put a band with nodata cells into an integer dtype without a sentinel
- `ValueKind::Peak`, a third value kind for measurements whose largest values lie on lines one cell wide. Peak bands decimate by block maximum in `RasterSrc`, `CogSrc` and `GdalSrc`, and `Reproject`, `resample_to_grid`, `StacSrc` item warps and `Mosaic` take the largest input cell whose center lies inside each output cell, or the containing cell when sampling up. `Combine` samples a peak input from the containing cell, and every stac composite keeps a peak kind except `count`. `FlowAccumulation` pins `Peak`, so a channel one cell wide keeps its contributing area through reprojection, tiles and export overviews, where bilinear sampling blended it with its neighbours to about half. Layer file sources take `value_kind = "peak"`
- a chunk compute running when `Engine::invalidate` drops its entry no longer caches its result or writes it to the disk tier, so a source edited mid-compute is recomputed on the next pull instead of served from the old input. This holds for tile chunks and region chunks, and pulls waiting on the dropped entry compute from the edited input
- Raster caps carry a `Dtype` per band as `BandDtypes`, `PerBand<Dtype>` beside `BandKinds`: each integer format with an optional nodata sentinel, `F32` and `F64`. Elements that compute pin F64 with their value kind through `Constraint::pinned_value_kind_and_dtype`, and a `Cast` adapter registered after the reproject one widens a band losslessly when a link's dtypes differ. `RasterChunk::bands` is a `RasterBands` of terrano `TypedBand`s and `byte_size` counts each band's own sample width. Cropping, assembly, categorical resampling and mosaic, `QualityMask` and the stac item mask copy native samples, continuous resampling and mosaic and cog decimation narrow f64 back into the band's dtype, and the png and geotiff encoders and `export::write_cog` write the band's format and sentinel. Spill files are version 3 with a sample format per band, and version 2 files are deleted and recomputed. Every source still serves F64, so no output changes
- `Transform::region()` makes a region transform. Its node computes once per ladder level and pull time over the region aligned to that level, caches the result as the node's one entry for the level, and cuts every pull's window out of it, nodata past the region and no upstream pull for a window outside it. A region whose aligned pixels times bands times 60 bytes exceed the engine's byte budget fails with `Error::RegionTooLarge`, naming the finest resolution that fits. The kernel run is a spawned task that still fills the entry when its tile request is dropped, and an invalidation meeting the region drops every level and time of the node. `Viewshed` is a region transform over its disc, so a disc spanning n tiles runs once per level instead of once per tile. `Transform::output_without_input` and `Viewshed`'s `spread` are gone
- `StacSearch::item_mask` takes an `ItemMask`, one asset and the codes it keeps, and a `stac` layer source takes `item_mask = { asset = "scl", valid_values = [4.0, 5.0, 6.0] }`. Each item's mask asset is read with its other assets, nearest, and the item has no value in any band where the code is nodata or not kept, so every composite skips it there and `latest` fills it from an older item. The mask asset is not a band of the source, so `median` runs over a search whose mask is categorical. `QualityMask` and the item mask share `mask_by_quality`. The `ndvi` example layer is now `red` and `nir` with an `item_mask` on `scl` and the `median` composite, so a pixel cloudy in the newest item takes the median of the clear items instead of rendering transparent
- `geoplumb`, a second binary in `geoplumb-server`. `geoplumb run <layers.toml> <layer> --bbox --crs --resolution [--t] -o <out>` builds the one named layer and writes a raster layer as a COG through `export::write_cog` on the grid `GET /export/{layer}` sizes, or a vector layer's features in the bbox as GeoJSON in EPSG:4326, with no time limit or value cap. `geoplumb info <file>` prints a COG's size, bands, sample format, bits, CRS, geotransform, compression, predictor, nodata and overview sizes. GeoPackage output is not written, see DESIGN.md
- `GET /export/{layer}` refuses a grid side past 4294967295 pixels, TIFF's 32 bit width, naming that limit before the value cap
- `LayerGraph` carries `chain_crs`, the crs the layer's ops run in, and `Layer` takes its crs from there instead of from the solved engine. `ExportQuery` and `DEFAULT_CACHE_BYTES` are public
- `Transform::output_without_input` lets an element answer a chunk before the engine plans or pulls its input. `Viewshed` answers NaN for a tile clear of the observer's disc, which used to pull and run the whole disc
- the window alignment's tolerance grows with the coordinates' size, `1e-12` of the largest coordinate in cells and at least `1e-9` cells, so a web mercator tile near x = 2e7 at z17 or z18 no longer pulls 257 columns
- `export::write_cog` stops pulling tiles once its future is dropped, so `GET /export/{layer}` stops after the tile it is on when it answers 504 or its client disconnects, instead of writing on to the last tile
- `GET /export/{layer}` writes its temp file under the new `GEOPLUMB_EXPORT_DIR` instead of the system temp dir, which is tmpfs on many hosts, and answers 500 naming the variable when it is unset. `router` takes that directory as a second argument
- `GET /export/{layer}` takes the crs authority in any case, `epsg:4326` as well as `EPSG:4326`
- value kinds are per band: raster caps carry `value_kinds: BandKinds`, one kind when every band shares it and one per band otherwise, and the `FieldMask` bit is `value_kinds`. `RasterSrc`, `CogSrc`, `GdalSrc`, `StacSrc` items in another crs, `Reproject`, `Mosaic`, `Combine`, `resample_to_grid`, the tile adapter and `export::write_cog` pick mode or nearest against mean or bilinear band by band, so a STAC search over `["red", "scl"]` no longer blends SCL codes into values like 4.5 that `QualityMask` then drops. Continuous output is unchanged. `RasterSrc::new`, `RasterSrc::from_geotiff`, `CogSrc::open`, `GdalSrc::open` and `GdalSrc::open_band` take anything that converts to `BandKinds`, a `ValueKind` meaning every band, and `resample_to_grid` and the cog `read_chunk` take `&BandKinds`
- `StacSearch::value_kind` is `StacSearch::value_kinds`, a kind per asset key with an asset left out continuous, and `StacSearch::asset_value_kinds` checks it against the assets and the composite. A `stac` layer source takes `value_kind = { scl = "categorical" }` beside the single `value_kind = "categorical"`, which still applies to every asset, and a key naming no asset fails at parse. The `s2-red-clear` example layer declares `scl` categorical
- `StacSrc` stacks assets of different pixel sizes instead of refusing them at open. Its grid is the anchor item's finest asset, and each item's same-crs assets coarser than that are read from their own overview for the pull, on their own pixel grid, and resampled onto the pulled window by `resample_to_grid` before the composite, nearest for a categorical band and bilinear for a continuous one. Earth Search's 10 m `red` with its 20 m `scl` now opens, so the `s2-red-clear` example layer starts, and the `ndvi` example layer lists `scl`, masks to SCL 4, 5 and 6 ahead of its `bandmath` and takes the `latest` composite
- `GpuContext::request` opens wgpu without `InstanceFlags::DEBUG` in debug builds too, so Vulkan objects carry no debug names unless `WGPU_DEBUG=1`. With several contexts submitting at once, libvulkan on mesa 26.0.8 lavapipe segfaulted in `vkSetDebugUtilsObjectNameEXT`, which crashed the wgpu tests in 9 of 20 parallel runs under coverage
- raster to vector elements: `Contours { interval, base }` turns a one-band continuous raster into one feature per elevation level, `Polygonize` a one-band categorical raster into one feature per class code, both on the raster's crs and chunk grid, with ids from the level index or the code so `dissolve` merges a level or a class across tiles, and seam points the same f64 in both neighbouring tiles. `Polygonize` refuses a continuous input at solve naming `value_kind` and a non-integer code at pull
- `Viewshed { observer_x, observer_y, observer_height, radius }` marks what an observer sees on a continuous DEM, 1 visible, 0 hidden, nodata past the radius, as a categorical raster. Every output tile computes the observer's whole disc, so chunked output equals whole output
- layer files take the ops `contours` (`interval`, and `base` 0 when absent), `polygonize` and `viewshed` (`lon`, `lat`, `height`, `radius`), lon and lat converted to the source crs at startup and radius in its units. A chain ending in `contours` or `polygonize` is a vector layer served as `.mvt`, and `viewshed` stretches over 0 to 1
- a raster pull whose window edge lies on a cell boundary no longer gains a row or column of nodata at degree resolutions: the window alignment's tolerance was a resolution-scaled length added to a cell count, 1e-12 cells at 0.001 degrees, below the rounding of the division
- tile clipping of lines drops every segment that runs along a tile's east or south edge, not only parts lying wholly on it, so a line that follows a seam and then turns into the west or north tile is no longer kept by both tiles and doubled by `dissolve`
- `VectorChunk::dissolve` joins line pieces that meet end to end in either direction, so a contour whose tiles ran it opposite ways merges
- `VectorChunk::dissolve` unions all polygon fragments of one id in a single topoi call. One call per fragment re-snapped the merged result each time, so later seams missed and a class over 16 tiles came back with up to 21 polygons too many or too few
- terrano 7ed5e85 and topoi 4d791e9: polygonize rings no longer touch themselves where two cells of a class meet at a corner, and topoi unions return OGC-valid polygons on an i64 grid, so `Polygonize` over 16 tiles of ESA WorldCover matches gdal's polygonize per class in polygon count, hole count and area
- `raster_vector_geojson` example: contours over a pixel window of a DEM COG, or polygons of a class raster, dissolved, written as GeoJSON
- categorical rasters: raster caps carry a `value_kind`, `Continuous` or `Categorical`, negotiated like dtype with its own `FieldMask` bit. Categorical values decimate by block mode (ties to the smaller code, an all-nodata block stays nodata) and warp and resample by nearest pixel in `RasterSrc`, `CogSrc`, `GdalSrc`, `StacSrc`, `Reproject`, `Mosaic`, `Combine` and `resample_to_grid`, so land cover and `reclassify` or `rasterize` output keep their class codes at coarse levels and across a reprojection. Continuous output is unchanged
- `RasterSrc::new`, `RasterSrc::from_geotiff`, `RasterSrc::from_grib`, `NetcdfSrc::open`, `CogSrc::open`, `GdalSrc::open` and `GdalSrc::open_band` take a `ValueKind`, `StacSearch` gains a `value_kind` field (continuous from `StacSearch::new`), `resample_to_grid` takes the kind as its last argument, `Mosaic` is built with `Mosaic::default()`, and `cog`, `gdal`, `stac`, `netcdf` and `grib` layer sources take `value_kind = "categorical"`, continuous when absent
- a fan-in's input links agree with each other only on the fields its constraint couples, every field under `Identity` and the passthrough fields under a `Derived` (`Constraint::coupled_fields`). `Combine` is now a `Derived` that leaves `value_kind` out, so it joins a categorical input with a continuous one, samples each by its own kind and outputs `Continuous`. `Mosaic` still needs one kind across its inputs. A link that fails negotiation names the caps fields with no common value, so a mixed mosaic fails naming `value_kind`
- `stac` composites over a categorical search: `latest`, `min` and `max` keep the kind, `count` outputs `Continuous`, and `mean`, `median`, `percentile` and `stddev` are refused by `StacSrc::open` and at layer-file parse, naming the composite. `Composite::output_value_kind` holds the rule
- `reclassify` and `rasterize` pin `Categorical` on their output, the terrain ops, `focal`, `bandmath`, the unary ops, `convolve`, `idw` and `combine` pin `Continuous`, every other element passes the kind through. Each source names its kind in `identity()`, so existing disk cache directories are not reused
- `netcdf` as a layer source, `source = { kind = "netcdf", path = "sst.nc", variable = "sst", datetime = "2024-01-01T00:00:00Z/2024-01-04T00:00:00Z", select = { zlev = 0 } }`, serving one variable of a NetCDF classic or 64-bit offset file as one f64 band. Lat/lon coordinate variables give EPSG:4326, projection x/y ones need `crs`. Rows are flipped north-up, 0 to 360 longitudes rotated to -180 to 180, CF `scale_factor`, `add_offset`, `_FillValue` and `missing_value` applied. A time dimension makes the layer answer `t`, a pull taking the latest step in its interval and an interval with no step serving nodata, and `/layers` publishes the first and last step as its temporal extent. A missing `datetime` beside a time dimension, an extra dimension missing from `select`, irregular spacing, non-square cells and a calendar other than standard or proleptic Gregorian fail at startup naming the file and variable
- `grib` as a layer source, `source = { kind = "grib", path = "gsm.grib2", message = 5 }`, serving one simple-packed GRIB2 field on a regular lat/lon grid through `RasterSrc::from_grib`, `message` counting each field of a multi-field message the way ecCodes does. Both scanning direction flags are honoured, bitmap holes are nodata, and another grid or packing template fails at startup naming it
- a fan-in layer publishes the time fields of its first input that has any, not only of a stac input
- a layer whose chain ends in features is a vector layer, served as Mapbox Vector Tiles at `/tiles/{layer}/{z}/{x}/{y}.mvt` through jung-mvt's encoder: one MVT layer named after the layer, the tile plus a 64 unit buffer of its 4096 extent, fragments cut at chunk seams dissolved back into one feature per id, feature ids as MVT ids, scalar properties as MVT values, arrays and objects as JSON text and nulls left out. `?t=` works as on raster tiles. A `geojson` or `gpkg` source no longer needs a `rasterize`, a vector layer takes no `gray` and fails at startup naming one, `.mvt` on a raster layer and `.png` or `.tif` on a vector layer answer 400, and so do the zonal endpoints on a vector layer. `/layers` gives each layer's `kind`, `raster` or `vector`
- `Reproject` takes vector links as well as raster ones, and `VecReproject` is gone. Its constraint is the new `Constraint::AnyOf`, a union of one `Derived` per kind, and `configure` picks the raster warp or the vector vertex projection from the fixated caps. One `Reproject::adapter()` bridges crs on links of either kind. Its `identity()` is `Reproject to=<crs>` for both kinds, so a raster layer's disk cache keeps its directory. From a geographic crs to EPSG:3857 vector fragments are clipped to EPSG:3857's latitude band, ±85.0511287798, before projecting, since projicio refuses the poles and a z0 pull reads lon/lat windows past -90
- every server layer ends in `Reproject` to web mercator, and the engine's caps on it say whether the layer is raster or vector
- jung-mvt is a git dependency on jung master
- `export::write_cog` writes a raster node over an `ExportGrid` in the node's crs as a deflate f64 COG through terrano's `write_cog_tiles`, one 512 px tile in memory at a time, each tile of each level pulled from the engine at that level's resolution and resampled by value kind, so overviews are not averaged. `export::overview_levels` holds the overview count rule tiletopia's export used
- `GET /export/{layer}?bbox=minx,miny,maxx,maxy&crs=EPSG:<code>&resolution=<units>&t=<interval>` on `geoplumb-server` streams that COG in any crs projicio knows, bbox and resolution in that crs. It builds an engine per request ending in the new `Reproject::onto_grid` on the export grid, refuses a bad bbox, crs or resolution and anything past 16384 x 16384 values with 400, runs two at a time with 503 for a third, and answers 504 after four minutes
- `Layer::build_all` takes the `Config` by value, each `Layer` keeping its `LayerConfig` and cache budget to build export engines from
- hydrology elements `FlowDirection`, `FlowAccumulation`, `Watershed` and `StreamOrder` over a one-band continuous DEM, each with a `crs` its input is reprojected into, refused when it is longitude and latitude, and a `region` it returns from `Transform::region`. They fill sinks and run D8 with terrano, and output ESRI codes, contributing area in crs units squared with the cell included, a basin label per outlet, and the Strahler order of the cells whose area reaches `threshold`. Layer files take them as `flow_direction`, `flow_accumulation`, `watershed` and `stream_order` with `crs = "EPSG:<code>"` and `region = [min_x, min_y, max_x, max_y]`, a layer ending in one names `gray`, and the ops after one run in its crs. `Error::RegionTooLarge` answers 400 on the tile, zonal and export routes

## 2026-10-29

A new `wgpu` feature on `geoplumb`, which the server does not enable, adds `GpuContext`, `Graph::with_gpu` and three elements: the solve splices `Upload` and `Download` wherever a tensor link crosses domains, and `WgpuConvolve` runs the 3x3 tensor convolve as a compute shader that matches `TensorConv` to 1e-5, NaN rule included. Wgpu chunks count against the context's own byte budget, never spill and are dropped on eviction, and a wgpu node's chunks assemble on the device

An 80 by 64 pixel pull over twenty 16 px tiles went from 260 submissions to 42 for its 240 dispatches. `GpuContext::submissions()` and `dispatches()` count both
- a gpu dispatch over the device's workgroup limit fails in its own compute instead of failing the batch it shares, and a batch submission that fails makes its `GpuContext` return an error naming that failure from every later call, since the engine has cached chunks whose buffers that batch never wrote
- `geoplumb_server::build_layer_graph` turns one `LayerConfig` into a `LayerGraph`: the graph with the layer's sources, fan-in and ops, its tip node and its `LayerInfo`, stopping before the web mercator reproject. `Layer::build` calls it and appends that reproject, so another crate can pull a layer file's layer onto a grid of its own choosing

## 2026-08-30

- every single-input raster transform the crate ships is now nameable in a layer file, taking `OpConfig` from four variants to nine: `focal` (`op` of mean, median, min or max, plus `radius`), `mask` (`band` and `valid_values`), `reclassify` (`classes` of `{ min, max, value }`, min inclusive and max exclusive), `unary` (`op` of `sqrt`, `abs`, `log`, or `{ add = c }` or `{ multiply = c }`) and `convolve` (a 3x3 `kernel`, plus a `scales` and `offsets` per band defaulting to one band unchanged), which the server builds as the three-transform raster to tensor, convolution, tensor to raster chain. What stays out of reach of a layer file is what needs a second input or another chunk kind: `Mosaic`, `Combine`, the vector and point sources, and the GeoTIFF encoder
- a layer may name `gray = { min, max }`, the value range the png encoding stretches over, overriding the range its ops imply. `focal`, `mask`, `unary` and `convolve` keep the range of the op before them, and `reclassify` leaves class numbers no op range covers, so a layer whose ops end in one is a parse error until it names its own `gray`

- composite reductions stop reading items a strip cannot use: a strip reads only the items whose footprint reaches its own rows, by the same footprint test the pull applies to the whole window, so strip time and pull time agree on an item, and a strip no item reaches comes back nodata without a read at all. `read_item` carries the same test before it opens an item's cogs, so any window that misses an item costs neither a reader open nor a decoded all-nodata chunk, on every path that reads an item. Values are unchanged: an item a strip misses only ever contributed nodata to those rows, and every reducer already skipped nodata

- `Median` and `Percentile` composites bounded spatially: a pull now cuts its window into horizontal strips whose pixels times stack depth times band count stay under a 4 Mi value budget, 32 MB of f64, and reads, reduces and drops each strip before reading the next, so peak residency follows the budget instead of the stack over the whole window. Measured over the same 512 KB window per item as the folding entry below: the stack path's peak used to grow 96 MB going from 64 items to 256, it now grows nothing (69 MB at 64, 52 MB at 256), while under the budget it still grows a window per item, the control the test keeps. Results are unchanged, not approximated: strips sit on the window's own pixel grid so a same-crs item reads the same file pixels a whole window read, and an item on another crs takes its source resolution from the whole pull window so two strips cannot pick different overviews. A window whose stack fits the budget takes one strip and is byte for byte the read and reduce it was before. The cost is latency on the deepest stacks: strips run one after another, so a stack needing N strips takes N passes of read latency, over the same distinct bytes since the tiles two strips share come from the `HttpRange` byte cache

- streaming composite reductions: `Mean`, `Min`, `Max`, `StdDev` and `Count` fold each item into per-pixel running state and drop its window, reading in waves of the 64-item parallel cap, so a pull's peak is one wave plus the running state instead of the whole stack. Measured by a counting global allocator over 64 items against 256: the folding peak grows 6.7 MB, the stack path's grows 96 MB, on a 512 KB window per item. `Mean`, `Min`, `Max` and `Count` are bit-identical to the stack reduction, items folding in the order it summed them; `StdDev` moves to Welford's method and agrees to precision, not bit for bit. `Median` and `Percentile` need every value at a pixel at once and keep the stack path unchanged. Latency is untouched: every intersecting item is still read
- zonal edge protections: a request to `POST /zonal/{layer}` or `/zonal/{layer}/series` takes one of four reduction slots and is refused 503 naming the cap when none is free, and a reduction outrunning four minutes answers 504. The slot is held by the blocking reduction rather than by the caller's request, because a reduction is a `block_on` and cannot be cancelled: a timed-out request keeps its slot until the work really ends, so the next request is refused instead of stacking another reduction on the blocking pool. This sits in the service rather than in the nginx in front of it so a direct caller and a differently deployed instance are covered by the same limits, which leaves rate limiting and connection caps at the ingress where they belong
- documented that overlapping zones resolve by burn order rather than erroring: request order decides, the last zone burned wins a shared pixel, so a zone contained in a later one reads as an empty row and a zone containing a later one keeps only what that one left. Every covered pixel counts once, proven by a contained-zone test in both orders
