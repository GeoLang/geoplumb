# Geoplumb design

Demand-driven geospatial compute engine. A distinct layer from geodukt (batch ETL to files) and fluvius (event streams): geoplumb computes at request time. With nubis it is the planned PDAL replacement.

## Data plane: pull only

The data plane is pull, permanently. A pull names a window (bbox plus target ground resolution). It flows sink to source, each transform rewriting it upstream via `plan`: a kernel widens by its halo, a reproject inverse-projects the bbox and rescales resolution by the local scale factor. Chunks flow back down, each transform producing exactly its requested grid via `compute`.

A pull may also name a time interval (`TimeInterval`, half-open UTC epoch milliseconds). It overrides the interval a time-varying source was configured with, and unlike the window it is not an element's to rewrite: `plan` implementations build their upstream request from the output one (`WindowReq::with_window`) and the engine reasserts the pull's time on whatever comes back, so it reaches every source as the instant asked for. Which nodes it reaches is a capability, not a name check: an element declares `time_varying`, the engine ors it over each node's parents at construction, and a node keys its chunks by the pull time only where that holds. A graph with nothing time-varying in it therefore keeps one entry per tile however many instants are pulled, and never confronts its sources with a time they do not understand. RFC 3339 lives with `StacSrc`, the only element that speaks it, the engine core carrying numbers.

- Batch is a degenerate pull: enumerate the chunk grid over an extent (`materialize`, or the pyramid example's tile loop) and pull everything.
- Live is invalidation plus re-pull: `Engine::invalidate` walks a dirty window downstream (widened by each element's `spread`, projected across CRS changes), drops overlapping cache entries, and publishes `Invalidation` events for drivers to re-render.
- Serving is a driver too: `geoplumb-server` builds one engine per layer from a TOML file (source plus an ordered op pipeline, ending web mercator and an encoder the request picks), and `GET /tiles/{layer}/{z}/{x}/{y}.png?t={start}/{end}` turns the query interval into the pull time, so a layer's instant is a request parameter rather than a deployment. A path ending `.tif` hands back the same tile as a GeoTIFF carrying every band in the bands' shared dtype, or f64 when they differ, with the colour table `Engine::palette` gives the layer's node, the suffixless and `.png` paths staying the gray PNG. Every layer ends in one `Reproject` to web mercator, and the engine's caps on that node say the layer's kind: a layer whose chain ends in features is a vector layer, every other layer a raster one. A vector layer serves `.mvt` only and a raster layer everything but `.mvt`, the other suffixes answering 400, and the zonal endpoints refuse a vector layer. An MVT tile pulls the tile bbox widened by 64 units of a 4096 extent at the tile's resolution, crops the assembled pull to that window, dissolves it per feature id and encodes it with jung-mvt as one MVT layer named after the geoplumb layer, feature ids as MVT ids, scalar properties as MVT values, arrays and objects as JSON text and nulls left out. A geometry collection goes out as one MVT feature per geometry type, all with its id, since MVT has no collection type. The served surface is a subset of what follows: a source is `stac`, `cog`, `gdal` (in a server built with the `gdal` feature), `geojson`, `gpkg`, `las`, `copc`, `netcdf` or `grib`, and `OpConfig` has twenty-two variants. Fifteen are every single-input raster transform the crate ships, `hillshade`, `bandmath`, `slope`, `aspect`, `focal`, `mask`, `reclassify`, `unary`, `convolve` (which adds the raster to tensor, 3x3 convolution, tensor to raster chain as three transforms), `viewshed`, `flow_direction`, `flow_accumulation`, `watershed`, `stream_order` and `cast`. `contours` and `polygonize` turn a raster into features, which makes the layer a vector layer unless a `rasterize` follows. `rasterize` burns a constant or a numeric property per feature, `idw` grids a point cloud into a raster band, and `vec_filter`, `vec_schema` and `vec_clip` rewrite features, ahead of a `rasterize` or at the end of a vector layer's chain. `deny_unknown_fields` holds over all of them, so naming any other element in a layer file is a parse error. A layer names either one `source` and one chain over it, or a list of `input` entries each with its own chain, a `fanin` of `mosaic` or `combine` (whose `op` is one of terrano's six binary operators) joining them, and a chain after the join. A `las` or `copc` source needs an `idw`, which the parse checks rather than leaving to the first tile. A `geojson` or `gpkg` input of a fan-in needs a `rasterize` before the join, which only the solve at startup checks. The in-memory GeoTIFF source, the tensor elements and the explicit reprojects stay unreachable from a layer file. The gray range the PNG stretches over comes from the last op that fixes one, or from the layer's own `gray = { min, max }`, which a layer ending in `reclassify`, `rasterize`, `idw` or one of the four hydrology ops has to name because class numbers, burned values, interpolated point heights, direction codes, areas, basin labels and stream orders carry no range of their own, as does a fan-in layer nothing after the join fixes a range for. A vector layer naming `gray` fails at startup. Everything else described below is reachable only from Rust code building a `Graph` against the crate.
- Event-stream processing (per-event latency, geofencing) is out of scope, that is fluvius.

## Caps negotiation

Adapted from glass2glass's CSP design (`crates/geoplumb/src/caps.rs`, `crates/geoplumb/src/solver.rs`, MPL-2.0). Elements declare a `Constraint`:

- `Produces(CapsSet)` — source shape
- `Identity(CapsSet)` — pass-through, optionally narrowing
- `Derived { input, passthrough, output }` — output derived from input, declarative: a `FieldMask` names the fields copied across, the override pattern pins retargeted fields (reproject pins `crs`)
- `AnyOf(Vec<Constraint>)` — the union of its members, for an element that takes several kinds and treats each its own way. A link goes through the members whose input accepts it, and in the backward sweep a member is narrowed only by the output pins it can produce, so a vector pin never narrows the raster member's input

Caps are kinded: a `CapsPattern` is a raster pattern (dtypes, bands, crs, resolution range, chunk px, value kinds), a point cloud pattern or a vector pattern (both crs, resolution, chunk px), or a tensor pattern (dtype, channels, crs, resolution range, chunk px, memory domain), and cross-kind intersection is empty, so a link always negotiates to one kind and a point source wired straight into a raster consumer fails with the usual empty-link error. A `Derived` whose output pattern has a different kind than its input is a cross-kind transform (`IdwGrid` takes points and makes a raster, `Rasterize` burns features into one, `ToTensor` and `ToRaster` cross the tensor boundary either way). Its passthrough mask projects the fields every kind shares, crs, resolution and chunk size, which is what lets a crs demand downstream of a gridder narrow the point link, and lets the reproject auto-plug fire downstream of it. The bands mask bit projects as a plane count where both kinds have one, raster bands to tensor channels and back, so a single-band consumer downstream of `ToRaster` narrows the channel count and a mismatched chain fails at solve time instead of emitting bands its caps never promised. Each field of a pattern is a `SetField`: `Any`, an exact `OneOf` in preference order, or `AtLeast`, an open lower bound for the fields where order means something. It intersects a `OneOf` by filtering the set to the values at or above the bound, another `AtLeast` by taking the larger bound, and fixates to the bound when nothing narrowed it to concrete offers, which is how `BandMath` demands the band count its expression reads without enumerating a ceiling. A new kind extends the pattern enum and the common-field projection, the solver stays kind-blind.

Each band of a raster has a value kind, `Continuous` (measurements), `Categorical` (class codes) or `Peak` (measurements whose largest values lie on lines one cell wide, like contributing area along a channel), and it picks how every resampling path treats that band. Continuous values decimate by block mean and warp and resample bilinearly. Categorical values decimate by block mode over the finite non-nodata values, ties going to the smaller code and an all-nodata block staying nodata, and warp and resample from the source pixel containing the sample point, so no path emits a value that is not one of the input's codes. Peak values decimate by block maximum over the finite non-nodata values, and warp, resample and mosaic to the largest input cell whose center lies inside the output cell, the output cell measured in the input crs (for a warp through `local_scale` at the window center), or to the containing input cell where no center lies inside, which is every output cell when sampling up. A channel one cell wide then keeps its value at every level and through every reprojection, where a block mean or a bilinear sample blends it with its neighbours. `Combine` samples a peak input from the containing pixel. Every peak output value is an input value, so peak bands are copied in their native dtype like categorical ones. Raster caps carry the kinds as `BandKinds`, one kind when every band shares it and one per band otherwise, so two layouts are equal exactly when every band's kind is, and every resampling path takes band i's kind from `BandKinds::band`. Sources declare it at construction: `RasterSrc`, `CogSrc` and `GdalSrc` take a `BandKinds`, which a single `ValueKind` converts to for every band, and `StacSrc` reads a kind per asset off `StacSearch::value_kinds`, an asset left out being continuous, and gives each of the asset's bands that kind. A `StacSrc` composite maps the search's kind to its output kind (`Composite::output_value_kind`): `Latest`, `Min` and `Max` keep it, `Count` is continuous whatever it counts, and `Mean`, `Median`, `Percentile` and `StdDev` keep a continuous or peak kind and blend values, so `StacSrc::open` refuses them over a search with a categorical asset and the server refuses them at layer-file parse, both through `StacSearch::asset_value_kinds`. The `StacSearch::item_mask` asset is always read categorical and is not a band of the source, so it never meets that check. Items are still decimated and warped by each asset's own kind. `MapAlgebra` with `Reclassify`, `Rasterize`, `Viewshed`, `FlowDirection`, `Watershed` and `StreamOrder` pin `Categorical` on their output, the terrain elements, `Focal`, `BandMath`, `ToRaster`, `IdwGrid`, `Combine` and the unary `MapAlgebra` ops `abs` and `multiply` by zero or less pin `Continuous`, `FlowAccumulation` pins `Peak`, the unary ops `add`, `sqrt`, `log` and `multiply` by a positive factor give `Peak` over an input whose every band is peak and `Continuous` over any other, since the largest of a non-decreasing function over a block is that function of the block's largest value, and every other raster element passes the input's kind through, so `Reproject`, `Mosaic` and the tile adapter read it from their fixated caps and `Combine` reads each input's from its own. A pin is a `Derived` whose passthrough mask leaves out the `value_kinds` and `dtypes` bits and whose output gives every band the one kind and the one dtype (`Constraint::pinned_value_kind_and_dtype`). A non-decreasing unary op is an `AnyOf` of two pins, the first taking only peak rasters, so a peak input solves to `Peak`. `BandMath` reduces any input to one continuous band, and `QualityMask` keeps every band, so each band keeps its kind through it. `Contours`, `Viewshed` and the four hydrology elements accept only a continuous input and `Polygonize` only a categorical one, so a raster of the wrong kind fails the solve naming `value_kinds`. Open value kinds fixate to `Continuous` on every band. The kind is part of the fixated caps, so it is part of the disk tier's graph hash, and each source names it in its `identity()`.

Each band of a raster also has a sample format, its `Dtype`: `U8`, `I8`, `U16`, `I16`, `U32` and `I32`, each with an optional nodata sentinel, and `F32` and `F64`, which mark absent cells with NaN. Two integer bands with different sentinels are different dtypes. Raster caps carry them as `BandDtypes`, `PerBand<Dtype>`, the same per-band list as `BandKinds`, which is `PerBand<ValueKind>`: one entry when every band shares it, one per band otherwise. `CogSrc` declares the file's format and nodata, `GdalSrc` each band's own type, `StacSrc` each asset's dtype under `Latest`, `Min` and `Max` and F64 under the other composites, and `RasterSrc`, `NetcdfSrc`, `Rasterize` and `IdwGrid` F64. An element that computes new values pins its output dtype with its value kind: `Viewshed` U8 with sentinel 255, reclassify the first of U8, I8, U16, I16, U32 and I32 whose range holds every class value below its maximum, with that maximum as the sentinel, or F64 when a class value is fractional, `ToRaster` F32, and every other computing element F64. `Reproject`, `Mosaic` and `QualityMask` pass the input's dtypes through, and open dtypes fixate to F64. `QualityMask::configure` refuses an integer band with no sentinel, which has no way to mark a masked cell.

The `Cast` element converts each band to a target dtype. `Graph::new` registers its adapter after the reproject one. The template passes every field but `dtypes`, the factory takes the demanding side's dtypes as the target, and `Cast::configure` refuses a band whose conversion loses values (`Dtype::widens_losslessly_to`). The lossless conversions are U8 to U16, I16, U32 and I32, I8 to I16 and I32, U16 to U32 and I32, and I16 to I32, each keeping the sentinel's value, every integer format of 16 bits or fewer to F32, and every integer format and F32 to F64, where a sentinel becomes NaN. A fan-in whose first input is U16 and second U8 splices a cast on the second input, and the reverse order fails at configure naming the dtype. `Cast::new`, which the layer file's `cast` op builds, converts to any dtype by the narrowing rule below. Both refuse to convert a band that has absent cells into an integer dtype with no sentinel. `Cast` narrows through `bands::narrowed_raster`, which reads a raster's own nodata value as absent.

`CapsSet` is preference-ordered alternatives of patterns. The solver alternates forward sweeps (narrow each output link through the node's constraint) and backward sweeps (consumers narrow producers, coupling backward through `Derived` only on passthrough fields) until the links stop changing: a fanin couples its input links through the shared consumer, so one sweep each way is no longer complete. Fixation then assigns concrete caps source-first by backtracking search, because a diamond can leave branch preference orders that disagree, where greedy per-link fixation picks a jointly impossible combination. The greedy choice is tried first, so chains and plain fan-out fixate as before. Failures are structured and name the link.

A fanin declares one `Constraint` that applies to every input link, and its input links agree with each other on the fields the constraint couples (`Constraint::coupled_fields`): every field and one kind under `Identity`, so all pins negotiate to matching caps, only the passthrough fields under `Derived`, whose output pattern pins the rest as a transform's does, and under `AnyOf` every field any member couples, or every field when a member is an `Identity`. `Combine` is the `Derived` one, its inputs may differ in value kind and its output is continuous. An empty link fails naming the caps fields with no common value between the two sides, computed from the patterns (`conflicting_fields`), so a mosaic of a categorical and a continuous input fails naming `value_kinds`.

An empty link is not always a failure. The graph carries a registry of `Adapter`s: a template constraint with the element's retargeted fields left free, plus a factory. On a failing link the solver checks each adapter generically, `template.output_set(offer) ∩ demand`, and splices the built element when the bridge is nonempty, so the solver never knows which caps field an adapter fixes. `Graph::new` registers a reproject adapter for raster and vector links alike, bridging crs, the target being whatever the demanding side prefers, at a fanin the first parent's. Its template is an `AnyOf` over both kinds and its factory reads the target crs from the bridged pattern of either kind, declining point cloud and tensor links. `register_adapter` adds more. Spliced nodes are appended after their consumers, so the engine and solver walk `topo_order` rather than index order.

Divergences from g2g, deliberate:

- Resolution stays a range on fixated caps and is resolved per pull by ladder snapping, because in a pull engine resolution is request-time, not negotiation-time.
- Field coupling is declarative (masks) rather than closure-based. Geo caps fields are independent enough that the closure machinery and passthrough probing are unnecessary.

## Chunks and snapping

Requests snap to a per-node grid: a power-of-two resolution ladder anchored at the node's origin (`GridSpec`), tiled at the negotiated chunk size. Cache keys are `(node, level, ix, iy, time)`, the time being the pull's at a time-varying node and `None` at every other, so time variants of a chunk live side by side without costing a time-invariant graph anything. A request finer than the ladder base clamps to level 0 and the driver upsamples, coarser requests snap to the finest level that is at least as coarse. The ladder is not unbounded: `snap_level` clamps at `MAX_LEVEL`, 31.

Chunks are self-describing (`RasterChunk`: bands, resolved bbox, resolution, crs) because responses are addressed by request, not stream order, and snapping may widen the window. A raster chunk holds its bands as `RasterBands`, terrano `TypedBand`s of one size, each in its own format: a `SampleGrid` of the integer type with its sentinel, a `SampleGrid<f32>`, or a terrano `Raster` for F64. `byte_size` counts each band at its own sample width. An element that does arithmetic reads a band through `TypedBand::to_raster`, which lends an F64 band's raster and widens the others with absent cells as NaN. Cropping, assembly, categorical resampling, a categorical `Mosaic`, `QualityMask` and the stac item mask copy samples in their own format. Continuous resampling, a continuous `Mosaic` and cog decimation widen, compute in f64 and narrow back to the band's dtype: NaN becomes the sentinel, or 0 with none, which is how GDAL fills integer pixels outside an image, a value rounds half away from zero and saturates at the type's range, and a value landing on the sentinel moves one step down, or one step up when the sentinel is the type's minimum, as GDAL's warp kernel moves a valid value off the destination nodata. `encode::png_gray` renders a sentinel cell transparent like a NaN one. `encode::geotiff` writes one uncompressed tile through `write_cog_tiles`, its sides rounded up to a multiple of 16, in the bands' shared dtype with the sentinel as GDAL_NODATA, or Float64 with no nodata tag when the dtypes differ, and writes the palette it is handed as a ColorMap. `export::write_cog` writes the link's format with its sentinel as GDAL_NODATA when every band shares one dtype, and Float64 with no nodata otherwise. `Chunk` is an enum over kinds: `Raster`, `PointCloud`, `Vector` and `Tensor`. A point chunk is the points inside one tile window, thinned for its ladder level, and point tile membership is half-open (x in `[min, max)`, y in `(min, max]`, the top edge inclusive because tiles step down from the origin) so a point on a seam belongs to exactly one tile. A vector chunk is feature fragments clipped to the tile window: each fragment carries the source feature's stable id (shared by every fragment of one feature, so a later dissolve can reassemble seam-split features) and its full property map. Points and lines use the tile membership convention, lines splitting into parts where they leave the tile and a part lying entirely on an excluded edge going to the neighbour that owns it, polygon rings clip independently against the tile rectangle (Sutherland-Hodgman, exact float math), which keeps even-odd fill correct for pixel centers inside the window. Multi geometries and geometry collections clip member by member and stay one fragment holding whatever survived, dropped only when nothing does. A tensor chunk is a contiguous CHW block of f32 over the tile window, in host memory or in a GPU buffer: channel-major, and inside a channel row-major with rows growing down from the top of the bbox, the raster order, so its length is always channels times the window's pixel count. The same pull, cache, coalescing, spill and invalidation machinery serves every kind, only assembly differs: rasters and tensors mosaic, point chunks concatenate and filter, vector fragments re-clip, concatenate and sort by id so burn order downstream matches source order.

Each node's grid derives from its parent's through `output_grid`: identity for most transforms, a reproject anchors the canonical origin for known CRS (web mercator, wgs84) and estimates base resolution from the local scale, or takes the origin and base resolution it was built with (`Reproject::onto_grid`), so a pull on that grid samples the source once instead of being resampled a second time off the default ladder. A fanin takes its finest input grid by default, and its elements sample inputs onto the output grid by value kind, bilinearly, from the containing pixel or from the largest covered pixel, exact when an input shares the output alignment.

## Runtime

One map per engine is both cache and coalescing table: a chunk entry is `Ready` (cached, LRU by tick, byte-budgeted), `Spilled` (on disk only), or `Pending` (in flight, with waiters). Concurrent pulls of one chunk share the computation. A cancelled computer's drop guard removes its `Pending` entry and wakes waiters, one of which takes over, so cancellation never wedges a chunk. Invalidation drops `Pending` entries too, and their waiters retry. Each `Pending` entry has an id that must match the one in its compute's `PendingGuard` for the result to be cached, so a compute whose entry was dropped or replaced returns its chunk to its own pull and neither caches it nor writes it to disk. Errors are not cached. A `Ready` entry records its memory domain: a `Wgpu` tensor chunk counts against the GPU byte budget of the graph's `GpuContext` instead of the engine's budget, is never written to the disk tier, and is removed outright when that budget evicts it, its buffer freeing once the last pull holding it lets go.

The disk tier (`Engine::with_disk_cache`) writes every computed chunk through to a flat binary file and marks the entry spilled once the file is safely down, so memory eviction demotes to `Spilled` instead of dropping. A spilled hit reloads through the same pending machinery, coalescing concurrent readers. The disk budget counts cold bytes only and evicts files LRU. Every `Source`, `Transform` and `Fanin` implements a required `identity()`, a string naming everything that changes its output: its parameters, a content digest for resident data, the tile layout for a COG, the path with its length and mtime for a local file, the url or search for a remote one. After the solve, so spliced adapters count, the engine hashes each node's index, kind, parents, identity and fixated caps in topo order with 64-bit FNV-1a, and the store is the subdir `geoplumb-<hash>` of the disk cache dir. A chunk file is written under a temporary name and renamed into place, so a chunk name never holds a partial write. The rename runs under the cache lock and only while the node's entry still holds the chunk written, otherwise the temporary file is deleted, so a write that finishes after an invalidation never replaces or deletes the file of the chunk computed after it. A file starts with a magic number and format version 3, and a raster file stores each band's sample format, its nodata and its samples at their own width. A file of any other version fails the read, and the engine deletes it and computes the chunk again.

A transform whose `region()` returns a bbox in its crs is a region transform, for a kernel whose value at a cell depends on cells arbitrarily far away. Its node has one entry per ladder level and pull time, keyed `ChunkKey { level, ix: 0, iy: 0, time }`, computed over the region aligned outward to that level's grid. Every pull at the node cuts its window out of that entry, with nodata past the region. A window that misses the aligned region gets nodata, an empty vector or point chunk, or a NaN tensor, with no entry and no upstream pull. `compute` gets the aligned region as `out` and an input covering `plan(out)`, which region elements plan as the identity because the region border is their boundary condition. Before the entry is looked up, a region whose aligned pixels times bands times 60 bytes exceed the engine's byte budget fails with `Error::RegionTooLarge`, naming the finest ladder resolution whose aligned region fits. Sixty bytes a pixel is the peak of terrano's `fill_sinks`, `flow_direction` and `flow_accumulation` over one region, so the cap bounds compute memory rather than the cached entry. Concurrent pulls of one level wait on the `Pending` entry like any chunk. The pull that inserted it pulls the region's input itself, and the kernel run is a spawned tokio task that holds the drop guard and writes the entry, so a tile request dropped mid-run leaves the run to finish and its waiters read the result instead of starting it again. The engine's cache map, budgets and disk tier sit behind one `Arc` for that task. Invalidation at a region node drops every entry of the node, all levels and times, when the dirty window meets the region aligned at the node's coarsest cached level, and passes that aligned region downstream as the node's dirty window. Region elements do not implement `spread`.

Transforms' `compute` is synchronous by contract, the engine offloads it to tokio's blocking pool when a runtime is present and runs inline otherwise. Source `read` is async so ranged HTTP reads do not block the executor.

Engine caps are immutable per instance (solve happens in `Engine::new`), so cache keys need no caps fingerprint until re-solve exists.

## Elements

Thin wrappers over sibling crates: terrano-core for kernels and GeoTIFF IO, projicio-core for CRS transforms. The engine repo carries orchestration, not math. `BandMath` is the exception that carries its own: it parses a band expression at construction into an ast (band variables, f64 literals, the four arithmetic operators, the six comparisons yielding 1.0/0.0 at a precedence looser than arithmetic, unary minus, and sqrt, abs, min, max, pow, log, exp and a three-argument `where(cond, a, b)`) and evaluates it per pixel into a single output band, window-local on an identity plan, with nodata entering as NaN and NaN propagating through every operator: min and max included since `f64::min` would otherwise return the other operand, comparisons and `where` included so a nodata pixel never reads as an answer.

`QualityMask` and `Focal` are window-local raster transforms. `QualityMask` checks one quality band (sentinel-2 SCL, landsat QA) against a keep-list of codes and writes NaN through every band where the code fails or the quality band is nodata, band count and order unchanged, so downstream band indices stay stable. `Focal` computes mean, median, min or max over the square window of side `2r+1` per band, radius in output pixels, planning the upstream window wider by exactly the radius: the widened box is still on the node's own grid, so outward alignment adds nothing and chunked output equals whole-window output. A nodata neighbour drops out of the statistic, a nodata centre stays nodata. The terrain elements (`Hillshade`, `Slope`, `Aspect`) stay thin over terrano's kernels, `Aspect` in compass degrees, north zero clockwise, flat cells nodata.

Nine elements implement `Source`. Five of them are raster sources, described here; `LasSrc`, `CopcSrc`, `VecSrc` and `GpkgSrc` come further down with their kinds. `RasterSrc` holds the whole dataset resident and serves ladder levels by block decimation, mean or mode by value kind. `RasterSrc::from_grib` builds one from a GRIB2 field, and `NetcdfSrc` holds one per decoded NetCDF time step, both through one function that turns a regular grid of cell centres in file order into a north-up raster: rows stored south to north are flipped, columns stored east to west reversed, and a longitude grid past 180 east shifted by 360 or, when it covers the globe across 180, rotated to start at -180. A grid covering 360 degrees whose cell edges miss -180 and 180, a 1 degree grid with a centre on 180 say, repeats its wrapped column at the short end, so the raster reaches past both and a pixel either side of the antimeridian reads the cell it lies in. Every byte is read by terrano: `NetcdfSrc` reads the header with `read_netcdf_metadata`, its coordinate variables whole and one step as the slice `read_netcdf_values` returns with the leading indices fixed, and `RasterSrc::from_grib` takes field `message` of `scan_grib`'s list and decodes it with `decode_grib_field`. What stays in geoplumb is CF and grid interpretation: which coordinate variable is latitude, longitude, projection x or y, or time, the time units turned into epoch milliseconds per step, the regular spacing and square cell checks, and the north-up assembly. A pull takes the latest step in its interval or, with no interval, in the configured `datetime`. `CogSrc` reads windowed over terrano's `CogReader`: each pull fetches only the tiles it touches at the file overview nearest the request, decimating the remainder the same way when the file pyramid is shallower than the request. It serves the file's own dtype: `CogSrc::open` takes it from level 0's sample format and nodata, refuses a file whose levels differ in either, and reads with `read_window_typed`. `read_window_typed` refuses an integer level with a transparency mask and no nodata, and `open` probes every level with a zero-pixel read so such a file fails at open. Given a nodata value, which the layer file's `nodata` passes, `CogSrc` instead reads through `read_window_bands`, treats cells equal to that value like the file's own nodata, and narrows into the integer dtype with that value as the sentinel. A window starting left of or above the image is placed into the chunk with `bands::picked`, the cells outside holding the sentinel, 0 without one, or NaN. Decimation takes the mode of a categorical band and the mean of a continuous one in f64 and narrows the result back. It serves every band the file carries, decoding each touched tile once for all of them and advertising the file's band count in its caps. Its transport is the `RangeRead` seam, with a local file impl in terrano and an async, multiplexed `HttpRange` here for remote files. `GdalSrc`, behind the `gdal` feature, serves any raster GDAL opens the same way: it picks the coarsest overview at or below the request by `CogReader::select_level`'s rule, reads the window from it at its native pixel size with `RasterBand::read_as` in the band's own type for UInt8, UInt16, Int16, UInt32, Int32 and Float32, an integer band's nodata becoming its sentinel and a float band's nodata NaN, and as f64 with nodata mapped to NaN for every other type, and finishes with `CogSrc`'s block decimation when the pyramid is shallower than the request. A `gdal::Dataset` is `Send` but not `Sync`, so it keeps a pool of opened datasets, a read taking one out or opening another when the pool is empty. `StacSrc` searches a STAC api at open to anchor its grid, crs and band count on the most recent item, then searches lazily per pull in two-degree lon/lat blocks kept in a bounded lru, so coverage follows the pulls instead of the open bbox. Every search follows the response's `next` links to the end, so `limit` is page size and never a coverage limit. Items whose declared band count differs from the anchor's are skipped, an item whose cog turns out to disagree fails the pull rather than being truncated, and so does an item asset whose dtype differs from the anchor's. Assets are read in their own dtype through `cog::read_chunk`, and `StacSrc::open` refuses an asset of the search whose integer dtype has no sentinel, since cells outside an item would read as 0 and hide every older item. `Min` and `Max` narrow their fold back into the asset's dtype exactly, being one of its values, and an empty window is built in the dtype its caller needs. An item on another crs is kept with the anchor-to-item transform attached: its assets read the region covering the output window on the item's own pixel grid, then warp onto the anchor grid through the same inverse-mapped sampling `Reproject` uses, so a pixel at a utm zone boundary is identical whether a graph node or an item produced it, and a same-crs asset at the source's pixel size takes exactly the unwarped path when the window's top left corner lies on the asset's pixel grid at the level read. An asset off that grid, an item tiled on another origin say, goes through the coarser assets' path, read on its own grid and resampled onto the window by value kind, where `read_chunk` would round the window onto its grid and read up to half a pixel off. Matched items' cog assets are lazily-opened `HttpRange` readers keyed by href (s3 hrefs rewritten to their public https form), and a pull combines the items covering its window according to the search's `Composite`. A search may name several assets for collections that spread bands across per-band cogs, sentinel-2's `red` and `nir` say: an item is kept only when every listed asset is present, and a pull reads every asset, bands concatenated in asset order, so a downstream `BandMath` sees one multi-band raster. The assets may differ in pixel size, sentinel-2's 10 m `red` beside its 20 m `scl` say. The source's grid is the anchor item's finest asset, and a same-crs asset coarser than it is read from its coarsest overview no coarser than the pull, or at full resolution when the pull is finer than the asset, over the window widened by two of its pixels and on its own pixel grid, then resampled onto the pulled window by `resample_to_grid` by each band's value kind. This happens per item ahead of the composite, so every composite sees aligned bands. A search may carry an `ItemMask`, one more asset and the codes it keeps, sentinel-2's `scl` and 4, 5 and 6 say. An item is then kept only when it has the mask asset too, and the mask is read with every item after the search's assets, through the same per-asset path as a categorical band, so a mask coarser than the grid is resampled nearest onto the pulled window. The anchor's mask asset must have one band. `read_item` writes NaN through each of the item's bands wherever the mask code is nodata or not a kept code, through `mask_by_quality`, the function `QualityMask` runs on a chunk, and drops the mask band. The source's grid, bands and caps come from the search's assets alone. Every composite reads its items through `read_item`, so a masked pixel is absent from that item's stack: `Latest` fills it from an older item, the reducers skip it, and a pixel masked in every item stays nodata. A `QualityMask` after the source masks the composite instead, which leaves a pixel cloudy in the newest item empty under `Latest`. The resample takes each value at a window pixel's centre, so the grids need not nest: an asset whose origin is off the finest grid's cell edges, or whose pixel size is not a whole multiple of it, is sampled the same way. An item on another crs needs nothing extra, since its warp already reads each asset at its own pixel size. The default, `Latest`, mosaics them most-recent-first band by band: a pixel is complete only when no band is NaN there, so an older item can patch one band where the newest had nodata and leave the rest alone, and the walk stops as soon as every band is filled. `Mean`, `Median`, `Min`, `Max`, `Percentile` (0..=100 clamped, linearly interpolated between the neighbouring ranks), `StdDev` (population) and `Count` are temporal composites: they read every intersecting item with no early exit and reduce per pixel per band over the finite values, so nodata drops out of the stack rather than poisoning it and a pixel no item covered stays nodata, count included. `Mean`, `Min`, `Max`, `StdDev` and `Count` fold item by item into per-pixel running state, a count beside a running sum, extreme or mean, so each wave of item windows is dropped before the next is read and a pull's peak is one wave however deep the stack. `StdDev` runs Welford's method over that state, agreeing with a two-pass variance to precision rather than bit for bit. `Median` and `Percentile` need every value at a pixel at once, so they bound the stack spatially instead: the window is cut into horizontal strips whose pixels times stack depth times band count stay under a fixed value budget, and each strip is read, reduced and dropped before the next is read, so a pull holds the budget rather than every item's whole window. A window whose stack already fits takes one strip, which is the read and the reduce a whole window did. Strips are exact rather than approximate: the strip bboxes sit on the window's own pixel grid, so a same-crs item read for a strip is the same file pixels the whole window read, and an item on another crs takes its source resolution from the whole pull window, so two strips cannot land on different overviews and leave a seam. Time is resolved at the source by default and on the pull when a pull asks: `datetime` picks the interval, the composite picks what the interval collapses to, so "summer 2025 median" is a source configuration, and a pull carrying its own interval overrides `datetime` for that pull alone. Completed searches are cached by block and interval, capped at 256 entries and 8192 matched item references. Active pulls keep their results through eviction, and live items are shared by href across cached blocks and pull times so their readers are too. The composite never moves, only the interval does. A whole collection then behaves as one raster with no local data, at any instant.

Two fanin elements. `Mosaic` takes the first input, wiring order, that has a value at each output pixel, and needs every input on one value kind. `Combine` samples both inputs onto the output grid, each by its own value kind, and runs terrano's binary op band by band.

The point cloud pair over nubis is the PDAL slot. `LasSrc` holds a cloud resident (LAS via nubis or in-memory), anchors its grid at the cloud bounds with base resolution estimated as the mean point spacing, and serves tile windows with per-level voxel thinning, one point per cell of the level's resolution, the point analogue of block-averaged decimation. `CopcSrc` reads a cloud-optimized point cloud through copc-reader's `CopcRangeReader`, from a local file or over HTTP. Open reads the header, the COPC info and the hierarchy pages, anchors the grid at the header's min x and max y, and takes as base resolution the root spacing halved once per level down to the deepest level holding points. A tile read fetches the nodes whose voxels intersect its window at levels 0 through the coarsest one whose spacing is at or finer than the request, all of them since COPC levels add density rather than replace it, so the level selection stands in for `LasSrc`'s voxel thinning. Remote reads go through a `copc_reader::RangeRead` adapter over `HttpRange`, its length from one HEAD request. A reader reads through `&mut self`, so a read takes one from a pool the way `GdalSrc` does, and a reader whose read failed is dropped rather than returned. `IdwGrid` is the cross-kind transform: it plans the upstream point window widened by its search radius (in output pixels, so every level sees a comparable neighborhood) and grids z by inverse distance weighting via nubis's windowed, radius-binned `idw_window`.

The vector pair over topoi mirrors it. `VecSrc` holds a feature collection resident (GeoJSON via topoi or in-memory), anchors its grid at the collection envelope with base resolution estimated as the median segment length, and serves tile windows by asking an R-tree over the raw-geometry envelopes which features can reach the window (exact, not a prefilter: Douglas-Peucker only removes vertices, so a simplified geometry stays inside its raw envelope and a feature whose envelope misses the window has no fragment of it to give), then simplifying those features whole (Douglas-Peucker at the level's resolution, deterministic, so every tile sees the same simplified geometry and seams stay consistent), dropping features whose envelope is smaller than a pixel (points and multipoints exempt, a collection measured whole so a small member rides along with a big one), then clipping to the tile. Level 0 is the raw geometry. `GpkgSrc` runs the same per-level pipeline over a GeoPackage feature table without holding it: a tile read is one query through the table's `rtree_<table>_<geom>` index, decoding only the rows whose envelopes touch the window with topoi's `read_geopackage_geometry`, ordered by primary key so fragment order is stable. Reads run on the blocking pool over up to four pooled read-only connections. Feature ids are the primary key, the crs is the table's EPSG srs unless the caller names one, and the base resolution is the `gpkg_contents` extent's longer side over 1024, since a median segment length would need every row. A table without the rtree is refused at open, it belongs to `VecSrc`. `Rasterize` burns fragments to a single-band raster via topoi's `rasterize`, a constant or a numeric property per feature (features without it are skipped), last feature in source order winning where burns overlap. Its coverage rules (pixel-center fill, endpoint-independent line traversal) are preserved under clipping at pixel-aligned tile edges, so it needs no halo and chunked output equals whole-window output.

Three window-local vector to vector elements sit between the two, the head of a geodukt pipeline. `VecFilter` keeps the fragments whose property equals a value, `VecSchema` renames, drops and adds properties, `VecClip` intersects each fragment with a static boundary: polygons through topoi's overlay, lines cut at their crossings with the boundary rings and kept where the midpoint is inside, points by containment. All three run per fragment on an identity plan, so chunked output equals whole-window output by construction and none of them needs a halo. `Reproject` handles vector links too, learning the kind from its fixated caps in `configure`. It plans the inverse-projected window the same way for both kinds, then a vector compute forward-projects every vertex and re-clips to the output tile, where a raster compute warps. Vertices only, no densification, so a long segment keeps its chord across the projection, the trade geodukt's reproject already makes. The vector grid probes the local scale one cell in from the input origin where the raster one probes a thousand, because a vector base resolution is a segment length and can be degrees wide. From a geographic crs (one whose proj4 definition is `+proj=longlat`) to EPSG:3857 the fragments are first clipped to latitudes within ±85.0511287798, EPSG:3857's area of use, where web mercator y reaches the half width of its square: projicio refuses to project the poles, and a pull reaching past the mercator square plans a lon/lat read past ±90. No tile covers anything beyond that latitude. Other crs pairs project unclipped, since the projicio version geoplumb pins exposes no area of use to clip to. `identity()` is `Reproject to=<crs>` for both kinds, the kind being part of the fixated caps the disk cache hashes beside it.

Three elements run terrano's contour, polygonize and viewshed kernels over raster tiles. `Contours { interval, base }` is a cross-kind `Derived` from a one-band continuous raster to vector caps on the same crs, resolution range and chunk size. It plans one cell of halo, so the marching squares straddling a seam run in both tiles over the same four cells, and clips its lines to the tile with `clip_geometry`. Two things make both tiles cut a contour at the same seam point bit for bit: terrano computes each level as `base + index * interval` and hands back each crossing as a cell plus the fraction of the way to the next cell's center, which depends only on the two cell values and the level, and map coordinates count from the nearer tile edge, which is the same f64 in two neighbouring tiles. A tile emits one feature per level, its id terrano's level index with the sign bit flipped so ids sort by elevation and its property `elevation`, so `dissolve` stitches a level back together across tiles. A square with a nodata corner carries no segment, so lines end on the centers of the last valid cells around a hole.

`Polygonize` is the same cross-kind `Derived` from a one-band categorical raster. Terrano's regions are 4-connected runs of one code inside the window, so it needs no halo and no clip. Ring vertices are cell corners mapped from the nearer tile edge, so a polygon edge on a seam is the same f64 in both tiles. A tile emits one feature per class code, its id the code with the sign bit flipped and its property `value`, and a code that is not an integer fails the pull.

`Viewshed { observer_x, observer_y, observer_height, radius }`, observer and radius in the input crs, takes a one-band continuous DEM to a one-band categorical U8 raster: 1 where the observer's eye sees the ground, 0 where terrain hides it, 255 past the radius and where the DEM has no value. It is a region transform whose region is the bbox of the observer's disc, so terrano's `viewshed` runs once per ladder level over the whole disc and every tile is cut out of that run. A chunked pull therefore equals a whole one, a tile clear of the disc is nodata with no DEM read, and a dirty cell in the disc dirties the whole disc, since one raised cell can hide everything behind it.

The tensor trio is pure Rust and holds the model slot open. `ToTensor` scales and offsets raster bands into channels, `TensorConv` runs a 3x3 kernel per channel with one pixel of halo (a tap on NaN or off the window contributes zero, a NaN center stays NaN), `ToRaster` hands channels back as bands. The adaptation of the glass2glass model story is that a fixed model input size negotiates as a chunk size demand rather than an exact output shape: a consumer pinning `chunk_px` narrows every link back through both kind boundaries, so the tiles arriving at the model are the size it wants and everything upstream retiles to match. Growth is deferred until a consumer needs it: dtype is f32 alone, and layout is fixed CHW with no field to say so. A tensor link also negotiates a memory domain, `System` or `Wgpu`, and a pattern that names none is `System`, so every tensor element that does not ask for the GPU stays on the host. The domain is kind-specific like dtype and never projects across a `Derived`. Behind the `wgpu` cargo feature, which the server does not enable, `Graph::with_gpu` takes a `GpuContext` (a wgpu device, its queue and a GPU byte budget, from `GpuContext::request` or from a device the driver already holds) and registers two adapters, `Upload` for a system producer feeding a wgpu consumer and `Download` for the reverse, so the solve splices the transfer and a domain mismatch never reaches `compute`. A graph from `Graph::new` has neither, and a wgpu consumer in it fails the solve with the usual empty link. `WgpuConvolve` is `TensorConv` as a WGSL compute shader, the same plan, halo and NaN rule, run on the input chunk's own context. A wgpu chunk holds its buffer and that context, and a wgpu node's chunks assemble on the device, one window copy per chunk into a NaN-filled buffer, on the blocking pool like compute since the device calls block. Every window copy and convolve is recorded into the context's one pending command encoder rather than submitted on its own, and a download submits that encoder before its staging copy, so the copy sees every result recorded before it whichever chunk or node it came from, the queue running submissions in order.

`FlowDirection`, `FlowAccumulation`, `Watershed` and `StreamOrder` (`elements/hydrology.rs`) each take `crs` and `region`, a bbox in that crs, and `StreamOrder` also takes `threshold`. Each takes a one-band continuous DEM through an input pattern that pins `crs`, so over a source in another crs the solver splices a `Reproject` in front. `configure` refuses a crs whose proj4 definition is `+proj=longlat`, since D8 distances in degrees differ between the two axes, a crs projicio has no definition for, and a region that is not a finite box with area. The region and the crs, and the threshold, are in `identity()`. Each returns its region from `Transform::region`, so the engine computes the node once per ladder level over the region and cuts every pulled window out of that one result. Each plans the identity and crops its input to the output window before running a kernel, so the region border is the raster edge terrano's kernels treat as the outlet: flow from outside the region is not counted and a basin crossing the border is cut there. All four run terrano's `fill_sinks`, Priority-Flood with epsilon, then `flow_direction`, D8 with ESRI codes (1 east, 2 south-east, through 128 north-east, 0 where no neighbour is lower), so flow crosses filled depressions and flats toward their spill point. `FlowDirection` outputs the codes. `FlowAccumulation` outputs the contributing area in crs units squared, the cell included: terrano's `flow_accumulation` counts the cells upstream without the cell, so the element adds one and multiplies by the cell area. An area rather than a count gives a place about one value at every level. `Watershed` outputs terrano's `watershed`, one label per outlet in scan order. `StreamOrder` outputs terrano's Strahler `stream_order` over the cells whose contributing area is at least `threshold`, an area in crs units squared, nodata elsewhere. In a layer file the four ops take `crs = "EPSG:<code>"` and `region = [min_x, min_y, max_x, max_y]`, and the chain after one runs in its crs, so a later `viewshed` projects its observer there and an export in that crs pulls the op's node directly. A pull failing with `Error::RegionTooLarge` answers 400 on the tile, zonal and export routes, and every other engine failure answers 500.

Zonal statistics and per-step time series are pull drivers beside `materialize`, not elements: every transform computes one tile of its own grid and only sees that tile, so cross-tile aggregation per feature id has to sit above the graph. `zonal_statistics` burns the features' ids over each tile of the window (geometry unclipped, topoi's pixel-aligned sub-window burn hitting exactly the pixels a whole burn would) and folds band 0 into mergeable per-feature accumulators: count, sum, minimum and maximum, with mean read off them and median absent because it does not merge. One tile is resident at a time however wide the window. `zonal_time_series` runs one pull per caller-supplied interval and reduces each step the same way, and `window_statistics` / `window_time_series` are the featureless variants over the whole window.

`export::write_cog` is the third driver: it writes a raster node's output over an `ExportGrid` (north-west corner, pixel size and pixel counts in the node's crs) as a deflate COG of 512 px tiles through terrano's `write_cog_tiles` and `typed_tile_bytes`, in the link's dtype with its sentinel as the nodata tag when every band shares one dtype, and as f64 with NaN for nodata and no nodata tag otherwise, overviews down to about one tile and at most five (`export::overview_levels`). Each tile of each level is one engine pull of that tile's bbox at the level's own resolution, resampled onto the tile's exact pixels by the node's value kind, so an overview is the engine's answer at that scale rather than an average of the level below: codes stay codes, and a terrain op is computed on the coarser elevation. One tile is resident at a time, edge tiles padded with the sentinel or NaN past the grid. `Source::palette` is a source's colour table, `CogSrc`'s from level 0's ColorMap, and `Engine::new` carries it down through every transform and fan-in whose constraint passes dtypes through (`Constraint::passes_dtypes_through`), a fan-in only when every input has the same one, so any element that pins a dtype ends it. `export::write_cog` writes `Engine::palette` of its node as the COG's ColorMap. The palette rides on the solved graph rather than in caps or chunks: a caps field would make a `Mosaic` of two sources with different colour tables fail negotiation. `write_cog_tiles` calls back synchronously, so the whole write runs on the blocking pool and blocks on each pull through the runtime handle it was started from. A failed pull aborts the file and returns that pull's error.

Zones are burned in request order and the last one wins a pixel two of them cover, the rule `Rasterize` already follows. Overlap is therefore resolved, not rejected: a zone contained in a later one reduces to an empty row, count zero and null statistics, and a zone containing a later one keeps only what the later one left. Every covered pixel counts once, for exactly one zone, so the rows of an overlapping set still sum to the union rather than double counting it.

## Known limits

- The zonal endpoints bound one request by validation (pixels summed over steps, features, steps, ring positions, and axum's 2 MB body) and the service bounds how many run at once: four reduction slots, a request finding none free refused 503 naming the cap before an engine is touched, and a reduction outrunning four minutes answered 504. Four minutes sits under the five a proxy in front of the service typically allows, so a slow caller gets this reason rather than the proxy's. The slot belongs to the blocking reduction, not to the request: a reduction is a `block_on` on the blocking pool and cannot be cancelled, so a timed-out request keeps its slot until the work really ends and the next request is refused rather than stacking another one on the pool. The wait is bounded, the work is not. These live in `geoplumb-server` rather than in a proxy in front of it so a direct caller and a differently deployed instance get them too, which leaves what a proxy is actually for uncovered: there is no per-client rate limit and no connection cap, one caller can hold every slot, and the limits are per process, so N replicas allow N times the concurrency.
- `GET /export/{layer}` builds a fresh engine per request, reopening the layer's sources, ending in a `Reproject::onto_grid` to the requested crs on the export grid, or in the layer's own chain when that crs is already the chain's. It refuses past 16384 squared f64 values counted over whole 512 px tiles and bands, which keeps the file under classic TIFF's 4 GiB offsets, runs two at a time with a third refused 503, and answers 504 after four minutes. A timed-out or disconnected request drops the `write_cog` future, which sets a flag the tile loop checks before each pull, so the write stops after the tile it is on. The slot goes with the request, so for that one tile a third export can overlap. The file is written to an unnamed temp file under `GEOPLUMB_EXPORT_DIR`, read once at startup into the router's state, and streamed from it. Without that directory the route answers 500. Only raster layers export.
- The `geoplumb` binary of `geoplumb-server` runs the export route's planning and engine build (`Plan::from_query`, `engine_onto_grid`) over the one layer it names, with no slot, time limit or value cap, and writes a raster layer through `write_cog` or a vector layer's dissolved features in the bbox as GeoJSON, in EPSG:4326 only. Either goes to a temp file beside the output that is renamed when complete. GeoPackage output waits on geodukt: `geodukt-io`'s writers take `geodukt-core` types, `geodukt-core` depends on geoplumb itself, and geodukt's rusqlite 0.40 links a different `libsqlite3-sys` than geoplumb's 0.39, which cargo refuses in one graph.
- `CogSrc`, `GdalSrc` and `StacSrc` read a file's own overviews as they were written, and only decimate past the pyramid. A categorical or peak file whose overviews were built by averaging, as terrano's COG writer and GDAL's `AVERAGE` build them, serves blended values at those levels.
- `GdalSrc` serves a signed byte band as f64, since the gdal crate names `Int8` only when built against GDAL 3.7 or later, and so are 64-bit integer and complex bands. A band whose nodata its own integer type cannot hold fails at open. It refuses at open a rotated or sheared geotransform, non-square pixels and a dataset whose CRS has no EPSG authority. GDAL builds `AVERAGE` overviews counting NaN as a value unless the file declares NaN nodata, so a block with one NaN pixel is NaN in such an overview where `RasterSrc` averages the rest.
- The disk tier directory is named by the graph identity and outlives the engine. Opening it turns the files of time-invariant nodes into spilled entries, newest first up to the disk budget, and deletes the files of time-varying nodes along with partial writes, since a time-keyed chunk of a `Latest` composite can be stale a day later. `StacSrc` is time-varying, so nothing downstream of it survives a restart. A remote `CogSrc` or `CopcSrc` is identified by its url and its header and layout rather than its content, so a file replaced at the same url with the same layout is served from the old chunks until the directory is deleted, and a local file by its length and mtime, so a GeoPackage written only through its `-wal` file, which leaves the main file's mtime alone, is also served from the old chunks. Nothing deletes the directory of an edited graph, pruning old `geoplumb-*` directories is left to the operator. Two engines over one graph share a directory, and one deleting a file the other indexed costs the other a recompute.
- `CogSrc` holds one reader per file and `StacSrc` one per asset, and concurrent chunk reads run on that reader in parallel, with no lock between them. `StacSrc` keeps only items sharing the anchor item's per-asset band counts. An item's lon/lat footprint converts to the anchor crs, and a pull window's bbox back to lon/lat, through a densified envelope, sixteen segments per edge, so a rotated cross-zone quad keeps the far side two opposite corners alone would cut off and a window's tilted corner names every block it overlaps. Sixteen segments hold that envelope to the metre against a walk 256 times finer, up to a window a thousand kilometres across; a bbox containing a pole is the case no edge walk covers, since the pole itself lies on no edge. A search stops at 1000 accumulated items and a pull at 32 cold block searches, both failing rather than mosaicking thousands of items, and both applying per pull time the way they apply per source. `Median` and `Percentile` hold every intersecting item's values over one strip of the window at once, so depth costs latency rather than memory: the strips run one after another, and a stack deep enough to need several of them takes that many passes of read latency, over the same distinct bytes since the tiles two strips share come from the range cache. The strip budget counts the source's bands only, so an item mask's band, and the copy `mask_by_quality` writes, sit outside it while an item is being masked. An `item_mask` asset also listed in `assets` has its own reader, so each item decodes it twice, once per kind, its bytes fetched once through the range cache. An absurdly wide pull interval still reaches an absurd item count the way an absurdly wide `datetime` does. The item list does narrow per strip: a strip reads only the items whose footprint reaches its own rows, and a strip no item touches is filled as an empty window with no fetch at all. Item reads, and the asset reads within each item, run in parallel, asset reads capped at 64 in flight across every pull in the process, `Latest` and the folding reducers reading 64-item waves, so `Latest` keeps its early exit and a fold peaks at one wave. What still grows with the item count for every composite is the per-item search metadata and readers, tens of kilobytes an item against a window's megabytes. `HttpRange` dedups fetches through a process-wide lru byte cache (256 MB, compressed bytes as fetched, single-flight on misses): cog readers request an interior tile as the same exact byte range every time, so the concurrent chunks of a pull, and neighbouring pulls, stop re-fetching the tiles they share. Fetches are async and multiplexed on a small dedicated runtime, `read_ranges` fetching a window's tiles concurrently under a process-wide transfer bound, so fetch concurrency does not cost a thread per transfer. A cold pull is now bound by the link to the data: distinct bytes over path bandwidth plus a few latency waves. Serving from the data's region is the remaining lever, not more client concurrency.
- Invalidation spread uses the coarsest cached level per node, over-invalidating slightly, never stale. It retains on the chunk bbox alone, so a dirty window drops every time variant of the chunks it overlaps, over-invalidating in the same direction.
- `LasSrc` holds the whole cloud resident and a tile read scans only the base-grid bins its window touches, a plain LAS file has no windowed reader. `CopcSrc` is that reader for COPC files: it reads levels cumulatively, 0 through the one the request needs, with no voxel thinning, so a coarse tile carries whatever density the writer gave those levels, and like `LasSrc` it takes its crs from the layer, leaving a WKT CRS VLR in the file unread. copc-writer sets the root spacing to halfsize / 128 whatever the cloud's density, so on its files the base resolution can sit well under the real point spacing and the finest ladder levels all read every level. copc-reader merges chunk fetches less than 64 KiB apart into one range, so a tile of a small file fetches most of it. `IdwGrid` grids only z, intensity and classification ride along in point chunks but no element consumes them.
- Tensors are f32 and CHW only, and there is no inference element: running a model belongs outside this repo, the engine's job ends at handing it windowed tiles.
- The GPU path submits one command buffer per sixty-four dispatches or per download, whichever comes first, plus one for each download's staging copy. A dispatch over the device's workgroup limit fails in its own compute before it is recorded. A batch submission that fails anyway drops every dispatch in it while the engine still caches their chunks, so the context refuses every later call with an error naming that failure, and the driver builds a new context. `Download` crops on the device into a fresh buffer and maps that back with a blocking wait, one round trip per chunk. Wgpu chunks never spill, so a GPU budget under a pull's working set means recomputing them. A 3x3 convolve alone does not pay for the upload and download around it.
- `Viewshed`'s radius is in the input crs units, degrees over a geographic source. The region cap's 60 bytes a pixel is the hydrology kernels' peak, so it refuses a `Viewshed` disc whose kernel run would fit the budget. A cell whose value equals a contour level puts the crossing on that cell's center, where up to four segments can meet and terrano links them in scan order. gdal_contour moves such a crossing about 2e-7 of a cell toward the lower neighbour instead, so on an integer DEM at a round interval the two can draw a level differently there.
- A line lying exactly on a pull window's max_x or min_y edge belongs to the neighbouring tile and is excluded from the window, the same rule a point there follows.
- `VecSrc` holds the whole collection resident. `GpkgSrc` does not, it holds a pool of open connections and decodes each tile's rows on demand. Both re-simplify their candidate features per tile read. A polygon edge lying exactly on a tile seam clips to a zero-area sliver in the neighbouring tile: harmless to a burn and to a dissolve, visible to anything that counts fragments. A segment passing exactly through a cell corner is a float tie and may burn one corner-adjacent cell differently between chunked and whole runs.
- `NetcdfSrc` keeps the step its `datetime` selects resident from open, and up to eight more decoded steps in an lru, each a whole 2-D grid as f64, so a global 0.25 degree variable costs 8 MB per held step. It reads classic and 64-bit offset files only, not NetCDF-4, CDF-5 or a julian, noleap or 360-day calendar, takes square cells only, and ignores `valid_min`, `valid_max` and the type's default fill value. `RasterSrc::from_grib` reads simple packing on a regular lat/lon grid only: complex, JPEG 2000, PNG and CCSDS packing, every other grid template and the column-major, alternating and staggered scanning modes fail at open.
- `GpkgSrc` reads XY ordinates only and leaves blob columns out of a feature's properties, since a blob has no JSON form. Its base resolution comes from the table extent rather than the geometry, so its ladder can start coarser or finer than `VecSrc`'s over the same features.
- A whole-window vector pull returns clipped fragments, and `VectorChunk::dissolve` merges them back per feature id. It is a call for pull drivers and sinks, the server's MVT route among them, not a graph element, because no element can do it: every transform computes one tile of its own grid, an identity-plan element is handed exactly the fragments of that tile, and whatever it returned would be re-clipped to the tile anyway. Merging is not bit-exact either way. All polygonal fragments of one id go through one topoi union, which snaps vertices to an integer grid sized to their bounds, so a merged ring equals the source geometrically but not bit for bit. A union per fragment re-snaps the growing result each time and later seams stop meeting. Line stitching matches endpoints within a few ulps, in either direction since terrano can link a contour backwards through a cell whose value equals the level: adjacent tiles solve the same Liang-Barsky ratio for a seam crossing, but re-clipping rebuilds a kept endpoint as start plus (end - start), which can land an ulp away.
